🚀 AI Data Analyst Platform

Full-Stack Agentic AI Platform — Deep Project Summary

1. Project Overview

The AI Data Analyst is a production-grade, full-stack platform that enables users to analyze structured datasets (CSV/Excel) and PDF documents using natural language. Instead of writing SQL or Python manually, users simply ask questions in plain English — the platform's agentic AI pipeline automatically generates SQL, executes it, and returns rich results including data tables, interactive charts, business insights, and actionable recommendations.

Additionally, the platform integrates a WhatsApp Business Chatbot module that allows businesses (gyms, clinics, coaching institutes, etc.) to automate customer engagement, lead capture, and AI-powered FAQ responses through WhatsApp.

In one line: "Ask your data anything in English — get SQL, charts, insights, and recommendations instantly, powered by a 20-node LangGraph agentic AI pipeline."

2. Why This Project Was Necessary

Problem Statement: In most organizations, data analysis requires SQL expertise and technical knowledge. Business users, managers, students, and non-technical stakeholders cannot directly query their data — they depend on data teams, creating bottlenecks.

5. Core Modules & Workflow

5.1 Module A — AI Data Analysis (NL → SQL → Insights)

This is the heart of the platform. A 20-node LangGraph agentic pipeline processes every natural language query through these stages:

User Query: "Top 5 expensive cars by average price" │ ▼ [1. Router Agent] ─── Classifies: sql | python | explain | refine │ ▼ [2. Memory Retriever] ─── Fetches session context (hierarchical RAG) │ ▼ [3. Planning Agent] ─── Creates step-by-step execution plan + mismatch detection │ ▼ [4. Schema Selector] ─── Picks only relevant tables (reduces errors ~40%) │ ▼ [5. SQL Generator] ─── Generates SQL with few-shot examples + plan │ ▼ [6. SQL Reviewer] ─── Two-pass review before execution │ ▼ [7. SQL Validator] ─── Syntax check via sqlglot │ ▼ [8. SQL Executor] ─── Runs on DuckDB (in-memory, fast) │ ▼ [9. Result Validator] ─── Checks for empty/error results │ ▼ [10. Stats Enricher] ─── Adds quantitative context (mean, min, max) │ ▼ [11. Insights Agent] ─── Generates 3-5 business insights with numbers │ ▼ [12. Web Scraper] ─── Fetches current news context (3s timeout) │ ▼ [13. Recommendations Agent] ─── Actionable business recommendations │ ▼ [14. Chart Agent] ─── Intent-aware auto chart (bar/line/pie/scatter) │ ▼ [15. Follow-up Agent] ─── Suggests 3 next questions │ ▼ [16. Memory Writer] ─── Saves turn to hierarchical session memory │ ▼ [17. Final Agent] ─── Assembles complete response → Frontend

Key Engineering Decisions:

  • Self-correcting SQL: Up to 3 retry attempts with error classification & recovery
  • Error classification: Distinguishes column errors, syntax errors, and type mismatches for targeted fixes
  • Few-shot examples: Generated dynamically from actual table/column names
  • Schema-first reasoning: LLM always sees the real schema, reducing hallucination
  • Intent-aware charts: Keywords like "trend" → line chart, "proportion" → pie chart
  • Academic domain detection: Auto-injects DBATU grading rules when student datasets are detected

5.2 Module B — Document Q&A (Vectorless RAG)

A novel "vectorless RAG" approach — no embeddings, no vector database. Instead uses LLM reasoning over a hierarchical document index:

Upload PDF → Extract Pages → Build PageIndex Tree │ User asks: "What is the admission process?" │ ▼ [Tree Search] LLM navigates hierarchical index → finds relevant sections │ ▼ [Page Retrieval] Extracts text from identified pages (max 8000 chars) │ ▼ [Answer Generation] LLM generates answer with page citations + confidence score
  • Supports PDFs up to 50MB
  • Tree search with max depth of 5 levels
  • Confidence scoring (0.0 – 1.0) on every answer
  • All Q&A history stored in PostgreSQL

5.3 Module C — WhatsApp Business Chatbot

Complete WhatsApp automation system using Meta Cloud API v21.0:

Customer sends "Hi" on WhatsApp │ ▼ Meta Webhook → POST /whatsapp/webhook │ ▼ [Find Client] Match business by WhatsApp number │ ▼ [Find/Create Lead] Auto-create CRM lead entry │ ▼ [First-time?] → Send branded greeting + interactive buttons [Returning?] → Route to AI reply engine │ ▼ [AI Reply Priority] 1. Document Q&A (if FAQ PDF attached) → PageIndex search 2. LLM Fallback → Niche-specific prompt (gym/clinic/coaching/etc.) │ ▼ Send reply via WhatsApp Cloud API + log all messages
  • Multi-niche support: gym, coaching, clinic, real estate, D2C, education
  • Lead management: status tracking (new → contacted → qualified → converted)
  • Analytics dashboard: leads by status, conversion rate, top interests
  • Interactive messages: buttons, list menus for guided conversations

5.4 Module D — Sandboxed Python Execution

For queries SQL can't answer (correlations, clustering, statistical tests), the platform generates Python code and executes it in a sandboxed subprocess:

  • 30-second timeout, restricted imports (only pandas/numpy/math)
  • Banned modules: os, subprocess, socket, requests (security)
  • Dataset limited to 10K rows for safety
  • JSON-serialized output capture

6. Hierarchical Memory System

Production-grade session memory with 4 layers:

LayerWhat It Does
Layer 1: Session SummaryLLM-generated summary of past analysis turns (non-degrading)
Layer 2: Structured EntitiesTables used, filters applied, aggregation types (extracted from SQL)
Layer 3: Recent TurnsLast 3 relevant turns with keyword-based relevance filtering
Layer 4: Last SQLInjected only for follow-up queries (intent detection)

Engineering features: Thread-safe with locks, session TTL (2hr), LRU eviction (max 1000 sessions), token-aware compression via LLM.

7. Authentication & Security

  • JWT-based auth: Access tokens (60min) + Refresh tokens (7 days) with DB-backed revocation
  • OTP email verification: bcrypt-hashed OTPs, 10-min expiry, rate limiting (60s), max 5 attempts
  • Password security: bcrypt hashing, timing-safe comparison, dummy hash for non-existent users
  • Refresh token rotation: Old token revoked on every refresh (prevents replay attacks)
  • Role-based access: User/Admin roles with hardcoded role assignment (no privilege escalation)
